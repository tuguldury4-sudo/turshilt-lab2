# Лаб 2 — k6 гүйцэтгэлийн хэмжүүр

Оюутны нэр — Я. Төгөлдөр

Оюутны код — B242270806

Тестийн бай нь локал Node.js сервер. `node server.js`-ээр асаагаад нөгөө терминалаас `k6 run script.js` гэж 30 секундийн baseline авна. Харьцуулах хэмжилтэд `k6 run --vus 5 --duration 1m script.js` командыг 30 ба 100 VU-д давтана. Шаталсан ачааллыг `k6 run stages.js` ажиллуулна.

Хэвийн SLO-д baseline p95-ыг миллисекундэд хөрвүүлж 1.5-аар үржүүлэн, 0.01 мс хүртэл дээш тоймлосон утгыг `P95_MS` болгон өгнө. Энэ нь бага ачааллын хэмжилтээс 50% орчим хэлбэлзлийг зөвшөөрнө. Хүсэлтийн алдааны босго 1%. `k6 run -e P95_MS=50 -e SLOW=1 slo.js` команд 100 мс зориудаар хүлээлгэдэг замыг ижил аргаар шалгаж, latency gate-ийг зөрчих ёстой.

Хэмжилтийн эх сурвалж нь `results/` хавтасны k6 гаралтууд.

## Дүгнэлт

5-аас 30 VU болоход throughput 4.99-өөс 29.87 хүсэлт/с хүртэл өссөн. Мөн энэ цэгт p95 2.95-аас 6.70 мс хүрч хэрэглэгчийн хүлээлт анх нэмэгдсэн. 100 VU-д throughput 99.51 хүсэлт/с болсон. Энэ ажиллуулалтад p95 4.17 мс болж буурсан тул хэмжсэн latency нэг чиглэлээр өсөөгүй. Гурван тогтмол ажиллуулалтад хүсэлтийн алдаа гараагүй. Шаталсан ачааллын нийлбэр p95 1.88 мс байсан бөгөөд тус бүрийн VU-ийн p95-ыг тусад нь хэмжих шаардлагатай. Тусдаа 30 VU SLO ажиллуулалт 3.56 мс гарч baseline-д үндэслэсэн босгыг хангасан. Зориуд хүлээлгэсэн endpoint 116.18 мс хүрч хатуу босгыг зөрчихөд k6 exit 99 буцаасан. [Шаталсан ажиллуулалт](results/stages.txt) · [Гаралтын зургууд](screenshots)
